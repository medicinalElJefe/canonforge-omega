# R110 — Unified Core Memory / Scar Trail

R110 extends the already-routed Unified Core replay surface rather than creating a second state authority.

The browser draft now edits `forecast_packet.memory[]` alongside typed relations and submits that same packet to `/api/core/evaluate` and `/api/core/replay`.

Memory fields remain bounded historical model inputs: sequence/time, scar burden, continuity, provenance, and evidence class. The UI plots scar and continuity across the draft sequence. Memory is not a new physical primitive, does not establish causation, and does not mutate canonical state.

R109 relation proof behavior, R107 replay boundaries, R106 schema compatibility, heartbeat truth, no execution, and no production policy mutation remain preserved.
