# OMEGA R174 — Federated Organ Fabric

R174 is an additive successor to the R169–R173 stateful swarm, reference-computation, heterogeneous-validation and Cloud↔Sovereign parity line. It turns previously recovered but unbound machine-service capability into a live part of the canonical OMEGA organism without changing the existing CanonState authority boundary.

## What becomes materially more real

The canonical `omegav6` Worker now binds all three existing Cloudflare federation services:

- `GENESIS -> omega-genesis-v1` — human/discovery convergence surface.
- `OMEGA_GENESIS_MACHINE -> omega-genesis-machine-r115` — deterministic `OMEGA_PACKET_v1` proposal machine.
- `OMEGA_OPTICAL_MACHINE -> omega-optical-machine-r115` — reduced-order screening and evidence-qualified `OMEGA_FULLWAVE_QUEUE_v1` escalation.

Before R174, the recovered swarm source already contained `GENESIS` and `OPTICAL_CHAIN` executors, but the canonical Wrangler configuration did not bind the two machine services. Those executor paths therefore remained gated at runtime. R174 closes that wiring gap.

## New R174 routes

### `/federation`

A live operator instrument showing:

- the 12-organ radial organism;
- the structural 144-branch address plane;
- live Genesis-machine and Optical-machine service status;
- organism mission launch profiles;
- mission progress from the stateful swarm coordinator;
- direct PROPOSE → SCREEN execution;
- the still-unresolved Sovereign full-wave gate.

The body map is structural instrumentation. Neutral address capacity is never painted as active computation.

### `GET /api/federation/r174/manifest`

Returns the complete organ map, execution profiles, live health state, hierarchy and truth boundary.

### `GET /api/federation/r174/health`

Probes the three Cloudflare service bindings and reports the stateful swarm/Workers-AI bindings. `FULL_FEDERATION_PROVED` remains false even when all cloud services are reachable.

### `POST /api/federation/r174/missions`

Launches a real stateful swarm mission through the existing `OmegaSwarmCoordinator`.

Profiles:

- `FOCUSED` → FLOCK / 24 cells.
- `ORGANISM` → TREE / 144 cells.
- `FULL` → FULL / 1,728 cells.

For an ORGANISM/TREE mission, the selected 144 cells cover all 12 domains × all 12 phases. Existing cell executor selection then makes the following recovered paths live:

- `GENESIS_MACHINE@ORCHESTRATION/FRAME`;
- `OPTICAL_CHAIN@PHYSICS/EXECUTE`;
- Workers AI on provider-eligible cells;
- deterministic bounded analysis on the remainder.

The mission remains candidate/receipt state and cannot directly mutate CanonState.

### `GET /api/federation/r174/missions/:id`

Reads the persisted swarm mission state.

### `POST /api/federation/r174/missions/:id/tick`

Explicitly advances a mission when an operator wants an immediate processing step rather than waiting for its Durable Object alarm.

### `POST /api/federation/r174/optical-chain`

Runs the machine-grade path directly:

`INTENT → Genesis R115 PROPOSE → Optical R115 SCREEN → evidence-qualified full-wave request candidate`

The returned R174 receipt hashes the intent, proposal, screened packet and optional Tier-2 job and preserves the complete lineage. A Tier-2 job is still only a request candidate; it is not an RCWA/FDTD result.

## Proof boundary

R174 does **not** promote any of the following into stronger evidence than they actually are:

- service reachability → scientific proof;
- deterministic Genesis proposal → validated geometry;
- reduced-order optical screening → Maxwell solution;
- Workers AI synthesis → observation;
- redundant cell execution → independent solver validation;
- queued `OMEGA_FULLWAVE_QUEUE_v1` → native execution;
- Cloud↔PC same-model parity → independent solver family.

The remaining closure condition is concrete:

`CURRENT AUTHENTICATED SOVEREIGN HOST → independent full-wave solver execution → persisted native receipt → independent-solver validation gates → OMEGA admission`

This is the next release frontier. R174 deliberately exposes that gate instead of claiming it has already passed.

## Woven Continuity mapping

The organism uses the established lifecycle directly:

`partition → exchange/transform → invariant carry → scar/residual carry → re-contextualize/repartition`

The 12 organ domains partition responsibility; service bindings and swarm tasks exchange/transform state; receipt hashes and lineage carry invariants; failures and unresolved proof remain scar/residual state; coordination re-contextualizes returned work without silently rewriting canonical authority.
